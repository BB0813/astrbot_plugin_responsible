## 2. 发现的模式

### 代码模式

本次变更体现出项目中常见的配置解析模式：

- 配置值可能来自外部插件设置，类型不稳定；
- 同一配置项可能出现：
  - `None`
  - 空字符串
  - 空白字符串
  - 数字
  - 数字字符串
- 业务语义上需要区分：
  - “未填写”；
  - “填写默认值”；
  - “填写 0 表示关闭”。

这类配置解析如果直接使用简单的 truthy/falsy 判断，很容易产生 bug。例如：

```python
value or 20
```

会把 `0` 错误地改成默认值；而：

```python
int(value or 0)
```

又可能把空值错误地解释成关闭。

因此项目中应避免对配置值使用过度简化的布尔判断。

### 架构观察

从 PR 描述和变更文件看，项目可能存在以下架构特点：

- `main.py` 承担较多业务逻辑与配置解析逻辑；
- 配置项解析可能没有独立的 schema、validator 或配置适配层；
- 插件设置与业务处理之间的边界较薄，外部输入容易直接进入业务流程；
- 默认值可能分散在业务代码中，而非集中定义。

这会导致配置类问题较容易发生，尤其是“空值”“0”“字符串数字”的语义混淆。

## 3. 规范完善建议

### 建议新增审查规则：配置项空值与 `0` 语义必须分开审查

对于所有配置项，尤其是数字型配置，应明确检查：

- `None` 是否表示未配置；
- `""` 是否表示未填写；
- `"   "` 是否表示未填写；
- `0` 是否是合法业务值；
- `"0"` 是否应与 `0` 等价；
- 默认值是多少；
- 默认值是否集中定义；
- 非法值如何处理。

特别规则：

> 不应使用简单 truthy/falsy 判断来解析具有业务含义的数字配置，尤其当 `0` 是合法值时。

### 建议新增审查规则：配置解析类 PR 应要求行为验证

对于配置解析修复，`py_compile` 只能证明语法正确，不能证明行为正确。

建议至少覆盖以下输入矩阵：

| 输入 | 期望 |
|---|---|
| `None` | 默认值 |
| `""` | 默认值 |
| `"   "` | 默认值 |
| `0` | 关闭 |
| `"0"` | 关闭 |
| `20` | 转发 20 条 |
| `"20"` | 转发 20 条 |

如果项目没有测试框架，审查中也应建议提供手动验证结果。

### 建议新增审查规则：默认值应避免多处硬编码

如果 `20` 是该配置项的默认值，应考虑：

- 是否已经在配置声明处定义；
- 业务代码中是否重复写死；
- README、配置 UI、实际逻辑是否一致。

推荐形成项目规范：

> 配置默认值应尽量集中定义，业务逻辑应复用同一默认来源，避免文档、配置界面、运行时行为不一致。

### 项目特有规范要点

针对 `bot_responsible` 这类插件项目，应重点关注：

- 插件设置中留空字段的实际传值类型；
- OneBot / 插件框架传入配置时是否可能统一转成字符串；
- 用户配置升级后的兼容行为；
- 私聊、群聊、转发消息等行为是否因配置解析错误产生副作用；
- 配置项关闭功能时，`0`、`False`、空字符串之间的区别。

## 4. 经验教训

### 未来审查应关注的要点

1. **配置解析不能只看“正常值”**
   
   应重点检查边界值和外部系统可能产生的类型变化，尤其是：
   - 空；
   - 空白；
   - 字符串数字；
   - 数字 0；
   - 非法字符串。

2. **`0` 是高风险配置值**
   
   如果一个数字配置允许 `0` 表示关闭，那么所有类似写法都要警惕：

   ```python
   value or default
   if value:
   int(value or default)
   ```

   这些写法都可能破坏 `0` 的业务语义。

3. **小 PR 也应检查完整调用链**
   
   即使变更只有几行，也应确认：
   - 解析结果类型；
   - 后续业务判断；
   - 默认值一致性；
   - 是否影响已有用户配置。

4. **编译验证不足以证明修复有效**
   
   `python -m py_compile` 是最低限度验证。配置类 bug 最好通过行为用例验证，否则很容易出现“代码能运行，但语义仍不对”。

5. **审查评论可以更有信息量**
   
   本次没有留下评论是可以接受的，但可以考虑增加一个非阻塞建议，例如：

   > 建议后续补充配置解析测试，覆盖 `None`、空字符串、空白字符串、`0`、`"0"` 等场景，避免后续回归。

   这样既不阻塞小修复合并，也能沉淀质量要求。
